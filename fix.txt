전체 소스와 빌드 설정을 확인했습니다. **가장 먼저 해결할 부분은 라이브러리 누락과 정상 사용자 오탐입니다.**

1. **[높음] 실제 서버에서 플러그인 활성화 실패 가능**
   [build.gradle:28](<G:/l7 def plugins/build.gradle:28>)에서 Caffeine을 `compileOnly`로 지정했지만, 대상 Paper 1.20.4 배포본에는 해당 라이브러리가 없습니다. Caffeine을 제외한 실행 검사에서도 클래스 로딩 실패를 재현했습니다. JAR에 포함하거나 `plugin.yml`에 [`libraries`를 선언](https://docs.papermc.io/paper/dev/plugin-yml/#libraries)해야 합니다.

2. **[높음] 정상 닉네임도 첫 접속부터 거부**
   [ConnectionListener.java:112](<G:/l7 def plugins/src/main/java/com/l7defense/listener/ConnectionListener.java:112>)에서 `Player123`, `123456`, `rhythms` 등이 무조건 거부됩니다. 닉네임 패턴은 다른 이상 징후와 함께 판단하고, 예외 허용 기능을 마련해야 합니다.

3. **[중간] 공격이 끝나도 경고가 계속됨**
   [SecurityManager.java:139](<G:/l7 def plugins/src/main/java/com/l7defense/manager/SecurityManager.java:139>)에서 누적 차단이 20건에 도달하면 계속 공격 상태로 남습니다. 시간을 11분 진행시킨 검사에서도 활성 차단은 0건인데 공격 상태는 유지됐습니다. 최근 일정 시간의 탐지량으로 판단해야 합니다.

4. **[중간] 접속 한 번을 두 번 집계**
   [ConnectionListener.java:118](<G:/l7 def plugins/src/main/java/com/l7defense/listener/ConnectionListener.java:118>)에서 닉네임 필터에 걸린 접속을 다시 기록합니다. 실제 3회 접속이 6회로 집계돼 IP가 차단되며, 같은 공유기를 사용하는 다른 이용자도 영향을 받습니다.

5. **[중간] ‘최근 접속 시도’가 실제로는 누적 수치**
   [SecurityManager.java:157](<G:/l7 def plugins/src/main/java/com/l7defense/manager/SecurityManager.java:157>)의 값은 시간이 지나도 줄어들지 않습니다. 차단된 IP의 접속은 일부 집계에서 빠져 운영자가 현재 상황을 잘못 판단할 수 있습니다.

추가로 **제한값의 설정 파일 분리, 개별 IP 차단 해제, 프록시 환경 대응**이 필요합니다. 현재 로그인 이벤트는 프로필 처리 단계에서 실행되므로, 초기 연결·핸드셰이크 부하까지 방어하려면 앞단 제한도 필요합니다. [Paper 이벤트 호출 위치](https://github.com/PaperMC/Paper-archive/blob/ver/1.20.4/patches/server/0175-Add-more-fields-to-AsyncPreLoginEvent.patch#L13)

**빌드는 성공했고 기본 접속·핑 제한도 확인했습니다.** 프로젝트에 자동 테스트는 없었으며, 별도 JVM으로 위 로직을 검사했습니다. 실제 서버 부하 테스트와 소스 수정은 하지 않았습니다.
